import DesklingCore
import DesklingSystem

let scheduler = ReminderScheduler(
    config: SchedulerConfig(
        interval: 45 * 60,
        quietHours: [12]
    ),
    clock: SystemClock(),
    idle: SystemIdleTimeProvider(),
    // Mic or camera in use: hold the reminder.
    busy: SystemBusyStateProvider()
)

// Call every 20 s or so.
if scheduler.tick() == .remind {
    showBreak()
}
using Deskling.Core.Scheduling;
using Deskling.Windows.System;

var scheduler = new ReminderScheduler(
    new SchedulerConfig {
        IntervalSeconds = 45 * 60,
        QuietHours = new HashSet<int> { 12 },
    },
    new SystemClock(),
    new SystemIdleTimeProvider(),
    // Mic or camera in use: hold the reminder.
    new SystemBusyStateProvider());

// Call every 20 s or so.
if (scheduler.Tick() == SchedulerDecision.Remind)
    ShowBreak();

Never prompts

Every system signal reads device and window state. Nothing opens the camera or microphone, nothing asks for Accessibility, nothing needs an entitlement you would have to explain.

Never phones home

No network code anywhere in the package: no analytics, no update checks, no telemetry. The Swift package has no dependencies at all.

One behavior, two platforms

The Swift code is the reference. JSON vectors generated from it are replayed by the C# port, so the two cannot quietly drift.

What's inside

Five Swift products and two NuGet packages. Take the pure logic alone, or the whole shell.

DesklingCore
Deskling.Core

Scheduling and pure logic

An interval timer with active hours and weekdays, quiet hours, an idle reset ("you were away, the timer restarts"), a hold while the user is busy with a grace period after, snooze, "after my next call" and pause. Runs on an injected clock, so it builds and tests anywhere Swift or .NET runs.

DesklingSystem
Deskling.Windows

System signals

Idle time since the last input. Whether another app is using the camera or microphone. Full-screen apps, power source and battery level, output muted and route, screen locked, light and dark appearance. Each exposes a current value and a change callback.

SystemIdleTimeProvider SystemBusyStateProvider SystemPowerSource SystemAudioOutput ScreenLockWatcher AppearanceWatcher

DesklingShell
Deskling.Windows

App shell

A window manager that shows the Dock icon only while a window is open, a login item toggle and "was I launched at login?", notifications with categories and actions, a global hotkey without Accessibility permission, a native tray icon and menu, single-instance startup, and drawing helpers for SVG paths, keyframes and a hand-drawn wobble.

The package ships no strings, product ids or window lists. Your app passes them in, already localized.

Knows you're on a call. Never asks.

A break reminder that pops up mid-meeting gets uninstalled. Deskling holds a due reminder while another app is using the camera or the microphone, and it finds out without ever opening a device, so there is no permission dialog and nothing for a reviewer to question.

If a device can't be read, it reads as not busy. Your app never blocks on a signal.

macOS Microphone
CoreAudio's list of processes using an input device.
macOS Camera
AVFoundation device state by default, CoreMediaIO for a sandboxed app without the camera entitlement, or off. The microphone alone catches nearly every call.
Windows Camera and microphone
The capability access consent store: Windows records when each app starts and stops using a device, and a start without a stop means it is in use now. No manifest capability needed.
Both Full screen
A full-screen app, game or presentation holds the reminder too.

Proven the same on both sides

Each scheduler behavior is written down once, as a JSON timeline generated from the Swift code. XCTest checks the Swift side reproduces it, xUnit replays every vector against the C# port. A change on one side fails the other side's build.

Install

One tag versions both sides. Deskling is 0.x until the second app has settled the API, so pin an exact version: minor releases may change public types.

Swift Package Manager

macOS 14+, Swift 6 language mode, no dependencies

// Package.swift
.package(url: "https://github.com/vmihalachi/deskling", exact: "0.2.0")

// then, per target
.product(name: "DesklingCore", package: "deskling")

Or in Xcode: File › Add Package Dependencies, paste the repository URL, pick Exact Version.
