# Layout

Where things live, folder by folder (moved from `AGENTS.md`). Every Swift file has a C# twin, at the same relative
path unless its row below says otherwise, so `grep -rn` on a type name finds both sides.

| Path | Contents |
|---|---|
| `Package.swift`, `Sources/Deskling{Core,System,Shell,Companion,CompanionUI,Store,Testing}/` | The Swift products (one folder each). `DesklingCore` imports Foundation only: `Scheduling/`, `Random/`, `Localization/`, `Settings/`. `DesklingCompanion` imports Foundation and Observation only: `Phrases/`, `Cadence/`, `Rules/`, `Settings/`, `Coordination/`, `Desktop/`, `Figures/`, `Skins/`; it and `DesklingTesting` (`Fixtures/`, and `Conformance/`: the suite, the generators, the standard case lists and `CompanionVectors` apps reuse) build on Linux. `DesklingShell` has `Speech/` (speaker, sequencer, voice library, chime) and the status item; `DesklingCompanionUI` (macOS) puts the companion on screen: signals, glyph, character view, desktop presence, delivery, notifier, `Theme/` (palette, spacing, speech bubble, status pill, the window chrome), `Shell/` (the app model apps subclass, its delegate, the menus, the copy structs), `Settings/` (rows and editors), `Support/` (the Support window) and `Screenshots/` (the screenshot script). A view or model here takes its words from the app: a `Text` per label or a copy struct, never a default. |
| `Tests/<Product>Tests/` | XCTest, one test target per product. `DesklingCoreTests/Conformance/` generates and replays `conformance/scheduler`, `DesklingCompanionTests/Conformance/` `conformance/companion`. `DesklingTestingTests` covers the test kit itself: the mocks, `MockStoreBackend`, `JSONValue`, `BankAudit` and the conformance suite. |
| `Tests/Fixtures/characters/` | Art sources for the fixture skins (`fixture-vector`: SVGs; `fixture-raster`: layer PNGs), compiled by `scripts/fixture-art.sh` into `DesklingTesting/Fixtures/Fixture*Art.swift` and `conformance/companion/characters/`. |
| `conformance/` | Generated vectors (`scheduler/`, `companion/`). Never hand-edit; `scripts/conformance.sh`. Formats in `conformance/README.md`. |
| `dotnet/Deskling.Core/` | Pure C# mirror of `DesklingCore`, file for file, plus `Store/` (mirrors `DesklingStore`; its `MockStoreBackend` mirrors `DesklingTesting`'s, shipped here because apps use it in preview modes). `IsAotCompatible`. |
| `dotnet/Deskling.Companion/` | Pure C# mirror of `DesklingCompanion`, folder for folder, plus the loaders `Phrases/PhraseBankJson.cs` and `Figures/CharacterArtJson.cs`. `IsAotCompatible`. |
| `dotnet/Deskling.Companion.Shell/` | The platform-free half of a companion app's shell (0.8, `plans/0.8/`): the C# twin of `DesklingCompanionUI`'s and `DesklingShell`'s logic, mirrored **by role, not file for file** (*The map* in `plans/0.8/README.md`), written against small interfaces (`ISpeaking`, `IChimePlaying`, `ITimers`, the signal sources) so its tests run on any OS. `Speech/` (sequencer, voice library), `Performance/` (`DeliveryPerformer`, phrase localization, pending ids), `Signals/` (`SignalHub` and its source interfaces), `Desktop/` (layout and placement in y-down screen coordinates), `App/` (`CompanionAppModel<TWindow, TSettings>` over an `ICompanionHost<TWindow>`, started as an `ICompanionLaunching`, the copy records, `CompanionMenus` building `MenuItem` data), `Screenshots/` (`SampleEnvironment`). `IsAotCompatible`. |
| `dotnet/Deskling.Testing/` | Mirrors `DesklingTesting` for .NET apps' test projects (no xunit): mocks, `Conformance/` (root, support, `Companion/*Replay.cs` bodies and `CompanionReplay`, one call per file kind), `Fixtures/` loading `conformance/companion/`, and `Shell/` (`ManualTimers`, `FakeSpeaker`, `FakeChime`, `FakeNotifier`, `FakeHost<TWindow>` with its status item, windows, desktop window) for the shell's tests. |
| `dotnet/Deskling.Windows/` | Win32 / Windows App SDK services (`net10.0-windows10.0.22000.0`, so Windows 11 and later; no XAML). Restores on Linux and macOS with `EnableWindowsTargeting`, but its Windows App SDK PRI step needs Windows: build it through `dotnet.yml`'s windows job. `System/` and `Shell/` (with `Shell/Localization/`). |
| `dotnet/Deskling.Windows.Companion/` | The Windows half of the companion shell (0.8, `plans/0.8/`), over `Deskling.Companion.Shell` and `Deskling.Windows` (`net10.0-windows10.0.22000.0`, Windows 11 like it; WinUI 3, code only: no XAML, so no resources an app must merge). `Speech/` (`Speaker`: recorded clips and the speech synthesizer through `MediaPlayer`, kept out of the system media controls; `ChimePlayer`), `Shell/` (`CompanionApp`, the app's `Application` and its `App.xaml` root: one copy running, a quiet launch at sign-in, reopening, and `Start` as the whole of `Main`; `WindowsCompanionHost<TWindow>` with the app's `CompanionViews`, `WindowManager<TWindow>` over `WindowSpec`s, `TrayStatusItem` with its glyph and panel, `GlyphRenderer`, `DispatcherTimers`, `CompanionNotifier`, `MenuConversion`, `ReduceMotion`), `Signals/` (the system's mute, lock, power and appearance as the shell's signal sources), `Views/` (`CharacterCanvas` with its pure `CharacterMotion`, `CharacterScene` and `CharacterImages`, posed through composition transforms on one `FrameClock`; `CompanionPalette` and `CompanionLook`, the look every control paints from; `SpeechBubble`, `StatusPill`, `ActionBar`, `PanelRow`, `Pointer`, `Space` and `WindowInset`), `Desktop/` (`DesktopCompanion` over `DesktopWindow`, a layered no-activate tool window that passes clicks through where the character isn't drawn), `Settings/` (the rows and editors, each over a copy record), `Support/` (`SupportWindow`), `Screenshots/` (`ScreenshotCapture`, `ScreenshotScript`). Builds and tests on Windows only, like `Deskling.Windows`. |
| `dotnet/Deskling.Core.Tests/`, `dotnet/Deskling.Companion.Tests/` | xUnit; `Conformance/` replays every vector (`scheduler/`, `companion/`). |
| `dotnet/Deskling.Testing.Tests/` | xUnit, any OS: the test kit itself, the mocks, `MockStoreBackend`, `ManualTimers`, the conformance helpers (root, support, the vectors' JSON) and the fixture loaders. |
| `dotnet/Deskling.Companion.Shell.Tests/` | xUnit, any OS: the Swift shell tests ported case for case (`SpeechSequencerTests`, `VoiceLibraryTests`, `DeliveryPerformerTests`, `DesktopLayoutTests`, `FloatingPlacementTests`, `CompanionAppModelTests` with the launch and host cases Swift can't run), over the Swift tests' own `Resources/Voice` and sunflower. |
| `dotnet/Deskling.Windows.Tests/` | xUnit for `Deskling.Windows`; runs only in `dotnet.yml`'s windows job. |
| `dotnet/Deskling.Windows.Companion.Tests/` | xUnit for `Deskling.Windows.Companion`, an unpackaged host; runs only in `dotnet.yml`'s windows job. Speech tests play generated WAVs at no volume: real playback where there is an audio device, the failure path where there isn't (a CI runner), and the line ends either way. The shell tests cover what runs without a WinUI app (the glyph's drawing and timing, the menu conversion, the placement next to the tray, the signal adapters, which launches show Home); the views' tests cover their pure parts (the character's scene and hit test against the pose vectors, the bubble's outline, the desktop bubble's place, the Settings rows' and Support's logic). Windows, the panel, the desktop character, notifications and the app's launch are checked by running the fixture app, and its screenshot run draws every window. |
| `dotnet/Fixture.App/` | The fixture app (Windows only, unpackaged, never packed): `Deskling.Windows.Companion` running `CompanionAppModel` over the fixture bank, the fixture vector character in the tray, XAML windows (Home, Settings, onboarding) and panel built from the package's controls (the character canvas, bubble, pill, Settings rows, `SupportWindow` over a mock store), the raster fixture from its PNGs, the desktop character, speech through the system voice, tones written at launch for the sounds, settings in memory. Home has the hand checks' controls: a long line to start a call during, a clock that skips to the next line, the desktop character on and off, the panel. Run it with `dotnet run --project dotnet/Fixture.App` (`--first-run` for onboarding); the checks still to do by hand are the issues labeled `hand-check`. `scripts/fixture-screenshots.ps1` renders its windows in light and dark. |
| `tools/` | Tools for companion apps, which vendor this repo as a `deskling/` submodule (`tools/README.md`): every one reads the app's `companion.json` (`companion.py`, `companion.schema.json`). `l10n.py`, `phrases.py`, `voice.py`, `character.py`, `synth.py`, `fonts.py`, the shell scripts (`verify.sh`, `setup-linux.sh`, `screenshots.sh`…), `hooks/hook.py`, `windows/` (the WinUI app kit: `companion.targets` every app's project imports, the screenshot runner and its layout check, the package smoke test, `check-winui.py`, `assets.py`), `store/` (the listing's checks, App Store Connect push, Partner Center import), `landing/` (`@deskling/landing`, published to npm) and `skills/` (the apps symlink them). Shared by every app, so no file names one. Tests in `tools/tests/` over `fixture-app/`. |
| `scripts/` | `verify.sh` (checks for what changed), `release.sh` (the next release: `plan` and `bump`, run by `release.yml`), `conformance.sh`, `fixture-art.sh` (compiles the fixture skins; `--check`), `agent-stop-check.sh` (`verify.sh --fast` as an agent Stop hook), `fixture-screenshots.ps1` (Windows: the fixture app's screenshot run). |
| `.agents/skills/` | Agent skills (see *Skills* in `AGENTS.md`); `.claude/skills`, `.junie/skills` and `.github/skills` are symlinks to it. `.codex/` holds Codex config and rules. |
| `plans/` | The design and sequence briefs of 0.5, 0.7 and 0.8, all released, kept as the record of why things are as they are (nothing new goes here: see *Planned work* in `AGENTS.md`): `plans/0.5/README.md` is the companion-layer design, `1-…`–`6-…` the sessions that built it; `plans/0.7/README.md` the companion shell (0.7.0: what the apps still repeat on top of 0.6 moves here), `1-…`–`6-…` its sessions; `plans/0.8/README.md` the Windows companion shell (0.8.0: `Deskling.Companion.Shell` and `Deskling.Windows.Companion`), `1-…`–`5-…` its sessions. |
| `.github/workflows/` | `swift.yml` (macos-26), `dotnet.yml` (ubuntu + windows), `release.yml` (tags → NuGet + GitHub release), `tools.yml` (the Python tools' tests), `regenerate-vectors.yml` (manual, on a branch: it refuses the default branch), `copilot-setup-steps.yml` (Copilot's cloud agent). |
